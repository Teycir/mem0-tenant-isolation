Summary
-------
With AUTH_DISABLED=false, the REST API authenticates callers but never binds the
user_id / agent_id / run_id namespace or the memory id to the caller's principal.
Any API key whose user has role="user" can enumerate all tenants via GET /entities
and then read, overwrite and delete other tenants' memories via
GET /memories?user_id=..., GET|PUT|DELETE /memories/{id},
GET /memories/{id}/history and POST /search.

Proof it is a bypass, not intended behaviour: the same role=user key returns
403 {"detail":"Admin role required to list all memories."} on GET /memories with
no identifier, and 200 once a victim user_id is supplied.

Affected
--------
Package: mem0ai (self-hosted server component, server/)
Version: 2.2.1, commit f1791da (the only build tested)
Severity: High, CVSS 3.1 8.8 AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H, CWE-639
