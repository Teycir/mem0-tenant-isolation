1) MEM0-2026-01 — Broken tenant authorization on memory endpoints
   High, CVSS 3.1 8.8 AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H, CWE-639/CWE-284
   Any API key with role=user can enumerate all tenants via GET /entities and then
   read, overwrite and delete other tenants' memories via
   GET /memories?user_id=..., GET|PUT|DELETE /memories/{id},
   GET /memories/{id}/history and POST /search.
   Negative control: the same key gets 403 on GET /memories without an identifier
   ("Admin role required to list all memories") and 200 once a victim user_id is
   supplied — a bypass, not intended scoping.

2) MEM0-2026-02 — GET /configure discloses internal infrastructure and
   unredacted credential keys
   Medium, CVSS 3.1 4.3 AV:N/AC:L/PR:L/UI:N/S:U/C:L/I:N/A:N, CWE-200
   GET /configure depends on verify_auth while POST /configure is admin-gated.
   Any authenticated key receives vector-store host/port/dbname/user and
   history_db_path. Redaction matches an exact lower-case key list, so
   aws_secret_access_key, client_secret, private_key, credentials_path are returned
   in clear when configured.
